You check training data for a dictation cleanup model. Each item has a TRANSCRIPT (what a speech recognizer wrote down) and a REFERENCE (the cleaned text the model will learn to produce). Check the REFERENCE against its own TRANSCRIPT, and nothing else: is everything the speaker meant still there, and nothing more?

A correct cleanup removes fillers, stutters, repeated words and false starts, keeps only the corrected side of a self-correction, fixes grammar and punctuation, and writes numbers in digits. It may lay the dictation out as a list or paragraphs, tidy list items into compact entries with details in parentheses, and drop pure asides with no content, thinking aloud ("let's see", "so yeah, I don't know") and mic checks ("can you hear me?"). Compacting wording is allowed; dropping a fact is not.

Headers: a lead-in, title or group label before a list ("Groceries:", "Pharmacy:") is optional, and adding one or leaving it out are both fine, with two exceptions. A header the speaker said themselves ("grocery list: eggs, milk", "okay, errands for Saturday") is content and must be kept. A header that misnames what it heads ("To-dos:" over grocery items, "Pharmacy:" over general errands) is wrong.

Check every item on three criteria. Judge each item on its own, and read its whole transcript: a correction near the end can change something said much earlier.

1. facts_complete: every item, quantity, name, date, time, amount, place, deadline, constraint, instruction, question, reason and meaningful hedge ("maybe", "probably", "I think", "I believe", with whoever the speaker says it came from: "I think Dana said 1,200") that the speaker kept is in the REFERENCE with the same value. Read a number said digit by digit one digit at a time: "oh four double seven" is 0477, "ab double two five" is AB225. A number keeps its scale: "40 over" meaning 40 thousand is not "$40 over". FAIL if one is dropped, changed, rounded or merged away: a single item from a long list, a detail folded into a label and lost, a header the speaker said, a sentence of content in the middle of a long dictation, a question turned into a statement. Removed fillers, stutters, repeats, false starts, the discarded side of a correction, and asides with no content are NOT dropped facts.
2. corrections_right: for each self-correction ("Tuesday, no, Wednesday", "scratch the eggs", "make that two", "carrots or actually no, let's go with peas", "the blue one, except it's too expensive, so let's go with the red one instead"), the REFERENCE keeps the speaker's final choice, not the abandoned one, and not both as if both were wanted. A late correction changes the value everywhere it was said: FAIL if the REFERENCE still states the old value where it first came up and only adds the fix later, or keeps an option the speaker moved away from in a summary of the changes. A reason the speaker gave for the change is content and stays. PASS when there is no correction.
3. nothing_invented: every fact in the REFERENCE traces back to the TRANSCRIPT. FAIL if it adds facts, names, numbers, context, greetings, sign-offs, conclusions, explanations, a title or attribution that misstates what was said ("from Dana" on a note written for Dana), or a currency or unit the speaker neither said nor clearly implied, or a header that misnames what it heads. Written forms ("five hundred dollars" as "$500"), punctuation, grouping, and a short label that fits what it heads are fine.

Return ONLY a JSON object, no prose and no code fence:
{"results": [{"i": 0, "facts_complete": true, "corrections_right": true, "nothing_invented": true, "note": ""}]}

Include one entry per item, with the item's index as "i". For a failing criterion, the note names what is wrong and quotes the words, for example "dropped '2 cans of chickpeas' from the list" or "kept 'Tuesday', which the speaker changed to 'Wednesday'".
